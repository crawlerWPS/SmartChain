## 1. 产品概述

### 1.1 业务背景

银行开展供应链金融业务时，面临以下核心痛点：

| 编号 | 痛点 | 业务影响 |
|------|------|---------|
| P-01 | 银行只能看到融资企业自身信息，无法全面了解企业在供应链中的真实位置和上下游关系 | 难以判断企业是否为真实供应链节点，融资决策依据不充分 |
| P-02 | 企业提交的合同、订单、发票、物流、验收等融资材料数量多，人工审核效率低 | 单笔业务审核周期长，客户体验差，人力成本高 |
| P-03 | 不同业务材料之间容易出现信息不一致（金额、主体、时间逻辑等） | 虚假贸易、材料造假风险难以及时识别 |
| P-04 | 客户经理难以及时发现供应链中的异常交易行为（循环交易、关联交易、异常新增交易关系） | 欺诈风险滞后暴露，损失难挽回 |
| P-05 | 缺少对企业供应链地位、交易真实性和融资风险的综合判断依据 | 风险决策依赖个人经验，标准不统一 |

### 1.2 产品定位

**产品名称**：供应链金融智能风控与尽调辅助平台（SCFS 平台）

**产品定位**：面向银行供应链金融业务人员（客户经理、风控审核员、规则经办岗、规则复核岗、运营主管、审计人员），通过供应链关系分析、材料智能审核、交易真实性核验和风险识别能力，辅助开展供应链金融业务。

**核心价值主张**：

| 价值维度 | 描述 |
|---------|------|
| 看清位置 | 帮银行看清融资企业在供应链中的真实位置 |
| 判断真伪 | 判断融资交易是否真实发生 |
| 提升效率 | 提高材料审核效率，缩短业务周期 |
| 提前预警 | 提前发现供应链中的潜在风险 |

**系统边界**：

- 本平台为**辅助决策系统**，输出风险提示与核验报告，不替代人工审批决策
- 不直接处理融资审批、放款、对账等核心资金业务
- 不直接管理客户主数据，但可调用客户信息用于核验

### 1.3 业务目标与衡量指标

| 编号 | 业务目标 | 衡量指标 | 目标值 |
|------|---------|---------|-------|
| OBJ-01 | 提升材料审核效率 | 单笔融资材料预审处理时间 | < 5 分钟 |
| OBJ-02 | 提升贸易真实性核验能力 | 核验报告产出时间 | < 30 秒 |
| OBJ-03 | 提前发现异常交易 | 异常交易识别覆盖率 | ≥ 95% |
| OBJ-04 | 降低误报率 | 风险预警误报率 | < 5% |
| OBJ-05 | 形成企业综合风险判断 | 风险画像生成覆盖率 | 100% |
| OBJ-06 | 全流程留痕可追溯 | 核验与审核记录完整率 | 100% |

### 1.4 适用业务范围

本平台服务于以下供应链金融产品：

| 产品类型 | 业务场景 |
|---------|---------|
| 保理融资 | 国内有追保理、无追保理、批量反保理、保理池融资 |
| 应收账款质押 | 基于应收账款的质押融资 |
| 订单融资 | 基于采购订单的融资 |
| 存货融资 | 基于仓单的融资（二期扩展） |

## 2. 用户角色与业务场景

### 2.1 用户角色定义

| 编号 | 角色 | 描述 | 核心职责 | 权限级别 |
|------|------|------|---------|---------|
| R-01 | 客户经理 | 对接融资企业的业务经理 | 发起融资申请、上传材料、跟踪核验进度、协调客户补充材料、参考风险报告辅助审批决策 | 业务操作 |
| R-02 | 风控审核员 | 风险审核岗人员 | 处理存疑核验案例、人工复核异常交易、出具风险审核意见 | 风控操作 |
| R-03a | 规则经办岗 | 规则配置经办人员 | 发起规则变更（创建/修改/启用/禁用规则、配置风险权重与阈值），直接维护材料清单模板与 OCR 模板 | 配置（经办） |
| R-03b | 规则复核岗 | 规则配置复核人员 | 审批规则变更、确认规则冲突 | 配置（复核） |
| R-03c | 运营主管 | 业务团队负责人 | 审核升级案例、监控运营指标 | 管理 |
| R-04 | 审计/合规人员 | 内审与合规部门 | 追溯核验全流程记录、审查审计日志、合规检查 | 只读全量 |
| R-05 | 系统管理员 | IT 运维人员 | 系统配置、用户权限管理、数据源接入管理、系统监控 | 系统管理 |

**双岗约束**：规则定义和风险权重配置必须遵循“经办岗提交、复核岗审批”的双岗机制；同一笔变更的经办岗与复核岗不能为同一人。材料清单模板和 OCR 模板由具备相应 RULE 权限的人员直接维护，操作后立即生效并记录审计日志。

**菜单权限**：
- 系统采用双层权限控制：菜单权限（控制用户可见的导航菜单）+ API 权限（控制接口访问）。
- 系统管理员（R-05）维护菜单树（目录/菜单/按钮三级结构），可为每个角色勾选可见菜单与按钮权限。
- 不同角色登录后看到不同菜单：例如客户经理（R-01）仅看到"工作台、图谱、审核中心"，规则经办岗（R-03a）看到"规则配置"菜单，审计人员（R-04）看到"审计查询"全量菜单。
- 菜单权限变更后，相关角色用户下次登录或刷新即可生效。
- 默认菜单分配（可由管理员调整）：

| 角色 | 默认可见菜单 |
|------|------------|
| R-01 客户经理 | 工作台、图谱查看、审核中心（我的申请）、材料管理 |
| R-02 风控审核员 | 工作台、图谱查看、审核中心（待审核）、核验报告 |
| R-03a 规则经办岗 | 工作台、规则配置（规则定义经办、风险权重经办、材料模板经办） |
| R-03b 规则复核岗 | 工作台、规则配置（待复核列表） |
| R-03c 运营主管 | 工作台、审核中心（升级审核）、运营监控 |
| R-04 审计人员 | 工作台、审计查询（全量日志、追溯） |
| R-05 系统管理员 | 工作台、系统管理（用户、角色、菜单、数据源） |

### 2.2 用户场景分析

#### 场景一：供应链融资申请辅助审核

| 项 | 内容 |
|----|------|
| **角色** | 客户经理 (R-01) |
| **触发条件** | 融资企业提交融资申请及贸易背景材料 |
| **前置条件** | 融资申请已建档、材料已上传 |
| **基本流程** | 1. 客户经理登录系统，打开待审融资申请<br>2. 系统自动识别材料类型并完成预审<br>3. 系统核验交易真实性并产出核验报告<br>4. 系统分析企业供应链位置与异常关系<br>5. 系统生成综合风险画像<br>6. 客户经理参考风险报告，协调客户补充材料并辅助审批决策 |
| **后置条件** | 风险报告归档，审批流程推进 |
| **异常流程** | 数据源不可用 → 触发降级策略，输出部分核验结果并明确标注 |

#### 场景二：客户经理尽调辅助

| 项 | 内容 |
|----|------|
| **角色** | 客户经理 (R-01) |
| **触发条件** | 客户经理需对企业进行尽职调查 |
| **前置条件** | 已输入目标企业标识 |
| **基本流程** | 1. 输入企业名称/统一社会信用代码<br>2. 查看企业供应链全景图（上下游关系、层级、角色）<br>3. 查看异常交易提示（循环交易、关联交易、异常新增）<br>4. 查看历史材料审核结果<br>5. 形成企业综合判断并输出尽调记录 |
| **后置条件** | 尽调记录归档 |
| **异常流程** | 企业无供应链关系数据 → 标注"信息不足"并提示人工尽调 |

#### 场景三：风控审核员处理存疑案例

| 项 | 内容 |
|----|------|
| **角色** | 风控审核员 (R-02) |
| **触发条件** | 系统核验结果为"存疑"或"高风险" |
| **前置条件** | 核验任务已完成并产出报告 |
| **基本流程** | 1. 审核员查看待处理存疑案例列表<br>2. 系统展示核验详情、异常项及风险提示<br>3. 审核员查看原始材料与证据链<br>4. 审核员做出人工判定（通过 / 拒绝 / 退回补充材料）<br>5. 录入判定理由 |
| **后置条件** | 判定结果写入核验记录，推送业务流程 |
| **异常流程** | 审核员无法判定 → 升级至运营主管 (R-03c) |

#### 场景四：规则配置（双岗机制）

| 项 | 内容 |
|----|------|
| **角色** | 规则经办岗 (R-03a) → 规则复核岗 (R-03b) |
| **触发条件** | 业务规则调整、新欺诈模式出现、监管要求变更 |
| **前置条件** | 经办岗具有规则配置权限 |
| **基本流程** | 1. 经办岗进入规则配置模块<br>2. 选择需调整的核验场景<br>3. 新增/修改/禁用规则，配置阈值与权重<br>4. 经办岗提交变更，状态为"待复核"<br>5. 复核岗收到待办，审查变更内容<br>6. 复核岗审批：通过 → 规则生效；拒绝 → 退回经办岗<br>7. 规则变更生效，记录变更日志 |
| **后置条件** | 规则变更生效，影响后续核验任务 |
| **异常流程** | ①规则配置冲突 → 系统提示冲突项，需经办岗调整后重新提交<br>②复核岗拒绝 → 退回经办岗，需修改后重新提交 |

**双岗适用范围**：规则定义（增删改）、风险权重配置（增删改）。材料清单模板与 OCR 模板不进入双岗审批，按权限直接维护并审计留痕。

#### 场景四b：运营主管监控与升级审核

| 项 | 内容 |
|----|------|
| **角色** | 运营主管 (R-03c) |
| **触发条件** | 案例升级、运营监控 |
| **前置条件** | 具有运营管理权限 |
| **基本流程** | 1. 监控运营仪表盘<br>2. 处理升级案例（高/极高风险）<br>3. 做出审批决策（通过/拒绝）<br>4. 录入决策理由 |
| **后置条件** | 决策结果写入核验记录 |
| **异常流程** | 无 |

#### 场景五：审计人员追溯核验记录

| 项 | 内容 |
|----|------|
| **角色** | 审计/合规人员 (R-04) |
| **触发条件** | 定期审计、合规检查、争议处理 |
| **前置条件** | 具备审计查询权限 |
| **基本流程** | 1. 按条件搜索核验记录<br>2. 查看单笔核验全流程记录<br>3. 查看核验快照（原始数据、核验结果、判定依据）<br>4. 导出审计报告 |
| **后置条件** | 审计结论记录归档 |
| **异常流程** | 核验记录不完整 → 标记为审计异常项 |

### 3.2 模块一：供应链全景关系图谱

#### 3.2.1 功能目标

构建企业之间的供应链关系网络，展示核心企业、各级供应商、经销商、物流企业、付款方、收款方之间的多维关系，帮助银行判断"**融资企业是否是真实供应链中的有效节点**"。

#### 3.2.2 功能详情

##### F-101 企业供应链关系展示

| 项 | 内容 |
|----|------|
| **功能描述** | 以关系图谱形式展示企业之间的多维供应链关系，支持查看企业上下游关系、供应链层级、合作企业数量、交易规模、合作时间 |
| **展示维度** | 采购关系、供应关系、合同关系、发票关系、物流关系、资金流关系 |
| **输入** | 企业标识（名称或统一社会信用代码） |
| **输出** | 关系图谱（节点=企业，边=关系类型）、节点详情、边详情 |
| **交互要求** | ①图谱支持缩放、拖拽、节点点击下钻；②支持按关系类型筛选显示；③支持按合作时间范围筛选；④默认展示一二级上下游，可逐级展开 |
| **业务规则** | ①合作企业数量统计去重；②交易规模按合同/发票金额汇总；③合作时间以最早一笔交易为准 |
| **优先级** | P0 |

**节点详情字段**：企业名称、统一社会信用代码、供应链角色（见 F-102）、合作开始时间、合作企业数量、累计交易金额、供应链层级。

**边详情字段**：关系类型、首次合作时间、最近合作时间、累计交易笔数、累计交易金额。

##### F-102 企业角色识别

| 项 | 内容 |
|----|------|
| **功能描述** | 自动识别企业在供应链中的角色并标注 |
| **角色定义** | 核心企业、关键供应商、一级供应商、二级供应商、普通供应商、边缘企业 |
| **识别规则** | ①核心企业：交易规模排名前 5% 且合作企业数 ≥ 30；②关键供应商：核心企业的一级供应商且合作时间 ≥ 3 年；③一级供应商：与核心企业有直接交易；④二级供应商：通过一级供应商与核心企业间接连接；⑤普通供应商：与核心企业距离 ≥ 3 级；⑥边缘企业：合作企业数 < 5 或交易金额 < 阈值（阈值可配置） |
| **输出字段** | 企业名称、供应链角色、合作时间、合作企业数、供应链影响程度（高/中/低）、可信程度（高/中/低） |
| **业务规则** | ①角色识别基于历史交易数据；②企业可同时具备多个角色（如既是核心企业又是关键供应商）；③可信程度由合作稳定性、合作年限、交易规模综合计算 |
| **优先级** | P0 |

**示例输出**：

```
企业A
  供应链角色：核心企业一级供应商
  合作时间：5年
  合作企业：35家
  供应链影响程度：高
  可信程度：高
```

##### F-103 企业供应链位置分析

| 项 | 内容 |
|----|------|
| **功能描述** | 针对融资企业，分析其在供应链中的位置与可信度 |
| **分析维度** | ①是否属于核心企业供应链体系；②与核心企业距离（层级数）；③上下游稳定程度；④是否存在真实交易关系 |
| **输入** | 融资企业标识 |
| **输出** | 供应链可信度评价（高/中/低/不足）+ 评价依据 |
| **业务规则** | ①融资企业未在供应链图谱中找到 → 可信度"不足"；②与核心企业距离 ≤ 2 级、上下游稳定 → 可信度"高"；③距离 3 级、上下游稳定 → 可信度"中"；④距离 ≥ 4 级或上下游不稳定 → 可信度"低" |
| **优先级** | P0 |

#### 3.2.3 异常关系识别

##### F-104 异常新增交易关系识别

| 项 | 内容 |
|----|------|
| **功能描述** | 识别企业短时间内大量新增供应商/客户的异常情况 |
| **识别规则** | ①统计企业过去 12 个月平均月度新增交易对手数；②若最近 1 个月新增数 > 历史月均 × 3，且新增数 ≥ 10，则触发预警 |
| **输出** | 预警标识"交易关系异常扩张" + 历史月均、当前新增、增长率 |
| **示例** | 过去一年供应商 20 家，最近一个月新增 80 家 → 触发"交易关系异常扩张"预警 |
| **优先级** | P1 |
| **参数可配置** | 历史时间窗口、倍数阈值、最小新增数 |

##### F-105 循环交易识别

| 项 | 内容 |
|----|------|
| **功能描述** | 发现企业之间形成 A→B→C→A 的资金或交易闭环 |
| **识别规则** | ①基于交易关系构建有向图；②使用环路检测算法（如 DFS）发现所有环路；③环路长度 ≥ 3 触发预警；④对环路中的资金流方向做一致性校验 |
| **输出** | 预警标识"疑似循环交易风险" + 环路路径（企业序列）+ 涉及金额 |
| **优先级** | P1 |

##### F-106 关联交易识别

| 项 | 内容 |
|----|------|
| **功能描述** | 发现关联企业之间交易过密的异常情况 |
| **识别维度** | ①企业法人关系（同一法人）；②股权关系（持股 ≥ 25%）；③高频交易关系（同一交易对手交易笔数占比 ≥ 50%） |
| **输出** | 预警标识"存在关联交易风险" + 关联关系类型 + 关联企业清单 + 交易占比 |
| **优先级** | P1 |

### 3.3 模块二：应收账款真实性辅助核验系统

#### 3.3.1 功能目标

围绕保理融资、应收账款质押、订单融资，通过材料信息自动识别与多材料交叉核验，辅助银行判断"**这笔贸易是否真实发生**"。

#### 3.3.2 输入材料

| 类别 | 具体材料 |

| 合同类 | 销售合同、采购合同 |
| 单据类 | 发票、订单、物流单据、验收单 |
| 应收类 | 回款记录、应收账款确认文件 |

#### 3.3.3 功能详情

##### F-201 材料信息自动识别

| 项 | 内容 |
|----|------|
| **功能描述** | 从上传材料中自动提取结构化信息 |
| **提取字段** | 买方企业、卖方企业、金额、材料对应日期、合同期限、付款期限、材料对应单据编号；底层通用字段按材料类型映射中文名称 |

| **输出** | 结构化数据（JSON）+ 原始字段位置标注（便于核对） |
| **业务规则** | ①提取置信度 < 90% 的字段标记"待人工确认"；②关键字段缺失触发"材料不完整"提示（联动模块三） |
| **发票展示规则** | OCR 结果页将 `transactionNo` 展示为“发票号码”，将原“商品”展示位调整为 `invoiceDate`“开票时间”；合同、订单及其他材料继续按类型显示合同编号、订单编号和对应日期 |

**典型提取示例**：

```
合同号：HT202601010001
买方：XX 股份有限公司（91310000XXXXXXXXXX）

金额：5,800,000 元
合同日期：2026-01-15
付款期限：合同签订后 60 天
```

##### F-209 OCR 识别模板配置

| 项 | 内容 |
|----|------|
| **功能描述** | 面向全部材料清单类型配置结构化识别模板，提高主体、信用代码、金额、单据号码及日期等字段的提取准确率 |
| **配置入口** | 规则配置 → OCR识别模板 |
| **模板属性** | 全局唯一模板编号、模板名称、材料类型、适用企业、优先级、启停状态、模板匹配关键词 |
| **支持类型** | 合同、发票、订单、物流证明、验收证明、回款证明、企业资质文件及后续材料清单扩展类型 |
| **字段规则** | 字段编码、页码、提取方式、锚点词或正则、归一化坐标区域、必填标识、最低置信度 |
| **提取方式** | `ABSOLUTE_REGION` 固定区域、`ANCHOR_REGION` 锚点相对区域、`FULL_TEXT` 全文正则 |
| **坐标约定** | 坐标原点为页面左上角，x/y/width/height 按页面宽高归一化为比例值；相对锚点允许 x/y 为负偏移 |
| **匹配规则** | 上传材料时可选择与材料类型匹配的启用模板；未选择时先按材料类型过滤，再校验模板匹配关键词，最后按优先级从高到低自动选取 |
| **样本设计** | 支持上传样本进行 OCR 分析、可视化配置字段区域，并在保存前测试字段规则提取结果 |
| **兜底策略** | 未命中模板或字段规则未提取到值时，继续使用通用信用代码、金额、编号正则；低置信度结果允许人工修订 |
| **权限** | RULE.view/create/update/delete；模板变更应写入审计日志 |
| **预置模板** | 标准贸易合同、标准增值税发票 |

##### F-207 客户及买卖方贸易关系维护

| 项 | 内容 |

##### F-202 主体一致性检查

| 项 | 内容 |
|----|------|
| **功能描述** | 比对合同、发票、付款等材料中的交易主体是否一致 |
| **检查项** | ①合同买方 = 发票买方 = 付款方；②合同卖方 = 发票卖方 = 收款方；③主体名称与统一社会信用代码匹配 |
| **输入** | F-201 提取的结构化数据 |
| **输出** | 检查结果（通过/异常）+ 不一致项详情（字段名、来源材料、值差异） |
| **业务规则** | ①主体名称模糊匹配（容忍简称、错别字）+ 信用代码精确匹配；②不一致触发"付款主体不一致"预警 |
| **优先级** | P0 |

**异常示例**：

```

```

##### F-203 金额一致性检查

| 项 | 内容 |
|----|------|
| **功能描述** | 比对合同、订单、发票、应收账款金额是否一致 |
| **检查项** | ①合同金额 = 订单金额 = 发票金额（含分批交付场景）；②发票累计金额 = 应收账款金额；③金额大小写一致 |
| **输入** | F-201 提取的结构化数据 |
| **输出** | 检查结果 + 金额比对明细表 |
| **业务规则** | ①分批交付场景支持累计比对；②金额差异 > 1 元触发"金额存在差异"预警；③允许合理的尾差（阈值可配置，默认 1 元） |
| **优先级** | P0 |

**异常示例**：

```
金额一致性：异常
合同金额：5,800,000 元
发票累计金额：5,750,000 元
差异：50,000 元
预警：金额存在差异
```

##### F-204 时间逻辑检查

| 项 | 内容 |
|----|------|
| **功能描述** | 检查合同、订单、发票、物流、验收等材料的时间逻辑是否合理 |
| **检查项** | ①合同日期 ≤ 订单日期 ≤ 发票日期 ≤ 物流日期 ≤ 验收日期；②各日期不晚于当前日期；③付款日期晚于验收日期 |
| **输入** | F-201 提取的结构化数据 |
| **输出** | 检查结果 + 时间轴可视化 + 异常项详情 |
| **业务规则** | ①发现"日期倒挂"（后序环节日期早于前序）触发"时间逻辑异常"预警；②日期为未来日期触发"日期异常"预警 |
| **优先级** | P0 |

**异常示例**：

```
时间逻辑：异常
异常项：发票日期（2026-01-10）早于合同日期（2026-01-15）
预警：日期倒挂
```

##### F-205 重复交易检查

| 项 | 内容 |
|----|------|
| **功能描述** | 识别重复发票、重复订单、重复融资材料 |
| **检查项** | ①发票查重：以"发票代码 + 发票号码"为唯一键，跨产品线查重；②订单查重：以"订单编号 + 买卖双方"为唯一键查重；③融资材料查重：同一材料在不同融资申请中的重复使用 |
| **输入** | F-201 提取的结构化数据 + 系统历史数据库 |
| **输出** | 检查结果 + 重复材料清单（含历史使用记录） |
| **业务规则** | ①查重范围覆盖系统内全部历史融资申请；②发现重复触发"存在重复融资风险"预警 |
| **优先级** | P0 |

##### F-206 真实性核验报告生成

| 项 | 内容 |

```

  ↓

  ↓
F-202 主体一致性检查
  ↓
F-203 金额一致性检查
  ↓
F-204 时间逻辑检查
  ↓
```

#### 3.3.5 降级策略

| 场景 | 降级处理 |
|------|---------|
| OCR 识别失败 | 关键字段缺失标记"待人工录入"，不阻断流程 |
| OCR 模板未命中 | 回退通用正则提取并保留原始 OCR 文本、坐标，供人工修订 |
| OCR 模板配置错误 | 保存时校验名称、材料类型和规则结构；识别时单字段失败不影响其他字段 |
| 外部数据源（税局/工商）不可用 | 仅做内部材料交叉核验，报告标注"降级核验" |
| 材料数量不足 | 跳过相关核验项，标注"材料缺失，无法核验" |

### 3.4 模块三：供应链金融材料智能预审系统

#### 3.4.1 功能目标

企业提交融资申请后，自动判断材料是否完整、是否符合融资要求、是否存在明显问题，辅助客户经理快速完成材料初审。

#### 3.4.2 功能详情

##### F-301 材料类型自动识别

| 项 | 内容 |
|----|------|
| **功能描述** | 自动判断上传文件所属的材料类型 |
| **识别类型** | 合同、发票、订单、物流证明、验收证明、回款证明、企业资质文件 |
| **输入** | 上传文件（PDF/图片/Word/Excel） |
| **输出** | 文件类型分类结果 + 置信度 |
| **业务规则** | ①置信度 < 85% 标记"待人工确认"；②识别失败标记"未识别"，提示人工指定类型；③同类型多份文件去重展示 |
| **优先级** | P0 |
| **与模块二关系** | 复用 F-201 信息识别能力，但 F-301 关注"是什么类型"，F-201 关注"内容是什么" |

##### F-302 材料完整性检查

| 项 | 内容 |
|----|------|
| **功能描述** | 根据融资业务类型生成所需材料清单，自动判断已提交、缺失、待补充 |
| **输入** | 融资业务类型 + 已上传材料清单 |

##### F-303 材料有效性检查

| 项 | 内容 |
|----|------|
| **功能描述** | 检查已提交材料是否在有效期内、是否完整、信息是否齐全 |
| **检查项** | ①材料日期是否超过一年；②OCR 是否完成；③按材料类型检查关键字段是否齐全：合同检查双方名称、金额、合同日期，发票检查购销方名称、金额、开票时间、发票号码，订单/物流/验收/付款检查对应编号、日期或金额 |
| **输入** | 已提交材料 |
| **输出** | 汇总总文件数、过期数、信息不完整数、异常材料数；逐份展示文件名、材料类型、OCR 状态、缺失字段、问题原因及“有效/异常”结论 |
| **业务规则** | 结果必须由当前材料及 OCR 数据实时计算并持久化，不允许使用固定返回值；重新检查时更新已有结果 |
| **优先级** | P1 |

##### F-304 企业信息一致性检查

| 项 | 内容 |
|----|------|
| **功能描述** | 检查不同材料中的企业主体信息是否一致 |
| **检查项** | 当前纳入总体结论的字段为①买卖方企业名称；②买卖方统一社会信用代码。法人和地址字段因当前 OCR 结构未提供，仅作兼容保留，不参与结论 |
| **输入** | F-201 提取的结构化数据 |
| **输出** | 总体是否一致、企业名称是否一致、统一社会信用代码是否一致、不一致数量及各来源材料值；界面统一使用中文“统一社会信用代码”，不展示“USCC检查” |
| **业务规则** | ①以申请登记的买卖方信息为基准，与各材料识别值按角色分别比较；②每个角色至少具有基准值和一份材料值才可判定一致；③重新检查前清理旧主表与明细，避免返回历史结果 |
| **优先级** | P0 |

**异常示例**：

```
企业信息一致性：异常
异常项：材料 A 法定代表人为张三，材料 B 法定代表人为李四
预警：企业主体信息不一致
```

### 3.5 模块四：供应链企业风险画像

#### 3.5.1 功能目标

综合企业供应链关系、交易真实性、材料审核结果，对融资企业形成综合风险画像，为银行审批决策提供风险判断依据。

#### 3.5.2 风险画像展示内容

| 类别 | 字段 |
|------|------|
| **企业基本信息** | 企业名称、所属行业、成立时间、注册资本、统一社会信用代码 |
| **供应链信息** | 所属供应链角色（来自 M1）、核心企业关系、合作企业数量、合作周期 |
| **交易情况** | 历史交易稳定性、交易金额变化趋势、异常交易情况（来自 M1 异常识别） |
| **材料情况** | 材料完整度（来自 M3）、材料真实性评分（来自 M2）、异常项数量 |
| **风险评价** | 风险等级、风险原因、建议关注事项 |

| 70-84 | 中风险 |
| 50-69 | 高风险 |
| < 50 | 极高风险 |

**风险等级阈值可配置**：评分分档阈值（85 / 70 / 50）同样遵循双岗机制（R-03a 经办、R-03b 复核）。

## 5. 业务流程

### 5.1 端到端业务流程（融资申请场景）

```
[企业] 提交融资申请 + 上传材料
  ↓
[系统] M3 材料类型识别 + 完整性检查
  ↓
完整性不足？─ 是 → [系统] 生成补正清单 → [企业] 补充材料 → 重审
  ↓ 否
[系统] M2 材料信息识别 + 多材料交叉核验
  ↓
[系统] M1 拉取供应链关系 + 异常交易识别
  ↓
[系统] M4 聚合三模块输出 + 生成风险画像
  ↓
[客户经理] 查看风险画像 + 核验报告
  ↓
风险等级？─ 低风险 → [客户经理] PENDING_REVIEW 审核 → 决策
  ↓
         ─ 中风险 → [风控审核员] RISK_REVIEW 复核 → 决策
         ↓
         ─ 高/极高风险 → [运营主管 R-03c] ESCALATED 升级审核 → 决策
  ↓
[系统] 记录决策结果 + 归档核验记录
```

### 5.2 状态机

**融资申请状态**：

| 状态 | 说明 | 流转条件 |
|------|------|---------|
| DRAFT | 草稿 | 企业提交 → MATERIAL_REVIEW |
| MATERIAL_REVIEW | 材料预审中 | 预审通过 → VERIFICATION；预审不通过 → SUPPLEMENT |
| SUPPLEMENT | 待补充材料 | 企业补充完成 → MATERIAL_REVIEW |
| VERIFICATION | 真实性核验中 | 核验完成 → RISK_ASSESSMENT |
| RISK_ASSESSMENT | 风险评估中 | 画像生成完成 → PENDING_REVIEW |
| PENDING_REVIEW | 待人工审核（低风险） | 客户经理决策 → APPROVED / REJECTED |
| RISK_REVIEW | 风控复核中（中风险） | 风控审核员决策 → APPROVED / REJECTED / ESCALATED |
| ESCALATED | 升级审核中（高/极高风险） | 运营主管 (R-03c) 决策 → APPROVED / REJECTED |
| APPROVED | 已通过 | 终态 |
| REJECTED | 已拒绝 | 终态 |

### 5.3 异常流程

| 场景 | 处理方式 |
|------|---------|
| OCR 识别失败 | 标记"待人工录入"，通知客户经理 |
| 外部数据源不可用 | 触发降级策略，输出部分结果并明确标注 |
| 核验规则冲突 | 系统提示冲突项，由规则经办岗（R-03a）调整后重新提交 |
| 审核员无法判定 | 升级至运营主管 (R-03c) |
| 核验记录不完整 | 标记审计异常项，通知系统管理员 |

## 6. 风险与合规

### 6.1 业务风险识别与缓解

| 风险类型 | 风险描述 | 缓解措施 |
|---------|---------|---------|
| 虚假贸易风险 | 虚构交易、伪造单据骗取融资 | M2 多材料交叉核验 + M1 供应链关系验证 + 异常交易识别 |
| 重复融资风险 | 同一应收账款/发票多次融资 | M2 F-205 跨产品线查重 |
| 关联交易风险 | 关联企业虚构交易套现 | M1 F-106 关联交易识别（法人/股权/高频交易） |
| 循环交易风险 | 资金或贸易闭环套利 | M1 F-105 环路检测算法 |
| 材料造假风险 | 伪造签章、篡改金额 | M2 主体/金额/时间一致性检查 |
| 操作风险 | 人工审核疏漏、标准不统一 | 系统化核验流程 + 标准化规则配置 |

### 6.2 合规要求

| 合规领域 | 要求 |
|---------|------|
| **审计追溯** | 全流程核验记录、人工判定、规则变更留痕，保留 ≥ 5 年 |
| **数据隐私** | 企业敏感信息脱敏展示，遵循《个人信息保护法》《数据安全法》 |
| **银行业监管** | 符合银保监会《商业银行供应链金融业务监管办法》要求 |
| **报告不可篡改** | 核验报告、风险画像生成后不可修改，支持版本追溯 |
| **决策可解释** | 人工判定需录入理由，系统判定需输出依据 |
| **辅助决策定位** | 系统输出为辅助决策参考，不替代人工审批决策 |

### 6.3 数据源降级与应急预案

| 场景 | 降级策略 |
|------|---------|
| 税局接口不可用 | 发票仅做 OCR + 内部查重，标注"降级核验" |
| 工商接口不可用 | 企业信息以材料中提取为准，标注"待核验" |
| 物流平台不可用 | 跳过物流轨迹核验，标注"人工核验" |
| OCR 服务不可用 | 整体流程暂停，通知系统管理员 |
| 数据库故障 | 切换备库，30 分钟内恢复 |
